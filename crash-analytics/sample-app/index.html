This service reports uncaught errors with the standard @sentry/node SDK. Each button below calls a real endpoint on this server. Endpoints marked breaks raise a genuine exception, report it, and answer 500. The process stays up, so you can fire them in any order.

Working endpoints

GET /api/checkout succeeds

Completes an order for a customer who is actually in the cache. Returns a receipt. Nothing is reported.


  


  

    

      GET
      /healthz
      succeeds
    

    
Liveness probe. Also echoes the release, environment, and where errors are being shipped.

    

      
      
    

    

  


  
Failing endpoints


  

    

      GET
      /boom
      breaks
    

    

      Checkout for a customer who is not in the cache. loadCustomer() returns
      undefined, so applyDiscount() throws a TypeError two frames deep.
      Good one for reading a stack trace.
    

    

      
      
    

    

  


  

    

      GET
      /boom/db
      breaks
    

    

      Inventory reservation against a database that never answers. Throws a custom
      DatabaseError, so it groups separately from the TypeErrors.
    

    

      
      
    

    

  


  

    

      GET
      /boom/async
      breaks (async)
    

    

      A payment settlement promise that rejects with nothing attached to catch it.
      Answers 202 immediately, then fails about 10ms later and is reported by the
      process-level unhandledRejection handler.
    

    

      
      
    

    

  


  

    

      GET
      /boom/repeat
      breaks N times
    

    

      Fires the same cart-badge TypeError N times in a loop. All N reports belong to one
      group, so your error tracker should show a single issue with a count of N, not N issues.
    

    

      
      
      
      
    

    

  


  

    

      POST
      /boom/pii
      breaks, carries secrets
    

    

      A payment audit that crashes while the request is carrying an
      Authorization: Bearer header, a password, an email, and a card number.
      The error report leaves this process with all of it attached. Check the issue detail in
      your error tracker: those values should be stored as [redacted].
    

    

      
      
    

    

  


  

    Prefer a terminal? curl -s localhost:3003/boom,
    curl -s "localhost:3003/boom/repeat?n=5",
    curl -s -X POST localhost:3003/boom/pii.
